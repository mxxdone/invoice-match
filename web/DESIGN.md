# 디자인 기준과 API 연결 경계

이 문서는 `web/` 디자인 시안의 인계 지침이다. P1-10 첫 연결 slice로 `/login`은 실제 `GET /api/me`에, `/cases` 목록은 실제 `GET /api/invoice-cases`에 연결됐다. 나머지 화면과 상세·작성·승인·인계는 아직 시안이며, P1-10 인수는 완료되지 않았다.

## 화면

| 경로 | 화면 | 현재 시연 |
|---|---|---|
| `/login` | 로그인 | 실제 로그인. 자격증명은 React 메모리에만 보관하고 `/api/me`로 서버 판정 |
| `/cases` | 사건 목록 | 실제 서버 페이징·부분 검색·AND 필터 목록. 요약 패널은 목록 DTO만 표시 |
| `/cases/new` | 청구 작성·수정 | 입력·행 추가/삭제·합계 미리보기·보완 수정 예시 |
| `/` | 청구서 상세·검토 | 비교표·행 근거·사유 모달·감사 탭, 정상·다섯 예외 예시 |
| `/handoff` | ERP 인계 상세 | 결과불명·인계 완료·실패의 상태 배치 |
| `/operations` | 운영 작업 | 대사 대상·인계 실패·결과불명 목록과 근거 패널 |

모든 계정·사건·금액·시간·식별자는 가상이다. 디자인용 탐색 메뉴는 모든 역할의 화면을 노출하지만 실제 권한을 구현한 것으로 간주하지 않는다.

## 유지할 디자인

- Ramp의 기본 표 프레임을 참고한 따뜻한 회색 사이드바, 흰 본문, 얇은 경계, 올리브 텍스트와 라임 포인트.
- 로고, 토큰, 탭, 표, 버튼, 패널은 공유한다. `globals.css`는 기본 토큰·상세, `screens.css`는 나머지 배치, `ui.tsx`는 공통 요소다.
- 카드 대시보드·새 테마·그래프·AI 채팅으로 임의 변경하지 않는다.
- 실제 데이터로 넘침·줄바꿈이 생기면 기능 Worker가 임의 재설계하지 말고 Head의 시각 검증을 요청한다.

## 후속 Worker가 구현할 경계

- API adapter와 view model을 도입해 고정 fixture를 교체한다. 시안 데이터는 서버 DTO가 아니다.
- 역할·소유권·자기승인·최신성·idempotency를 실제 계약에 맞춰 처리한다. 401/403/409와 데이터 없음·오류·로딩 화면을 구현한다.
- 일반 목록 DTO에 없는 합계·예외 상세를 별도 API 없이 추측하지 않는다. 목록 제출 시각은 `submittedAt`이며 작성 중에는 없을 수 있다.
- 운영 목록의 오류 요약은 현재 가상이다. 실제 handoff 조회와 결합할 때 N+1·집계 계약을 검토하고 필요한 변경은 별도 승인받는다.
- 작성 API는 사건 생성 → draft 저장 → 제출 흐름이다. 입력 합계는 확인용이며 서버를 대체하지 않는다.
- 보완 수정에서 사건 헤더는 편집 대상이 아니다. 실제 상태가 SUPPLEMENT_REQUIRED일 때 새 revision을 열고 제출한다.
- 검토는 화면에 표시한 동일 frozen subject version/hash를 사용하고 매핑 후 successorSnapshot을 반영한다.
- 지급 상태는 서버 값을 표시한다. 인계 완료를 송금 완료로 바꾸거나 결과불명에 재전송 버튼을 추가하지 않는다.
- 인증 시연을 실제 로그인 성공으로 취급하지 않는다. 비밀번호 저장·로그 기록을 금지한다.
- PDF/AI/RabbitMQ/DLQ는 이후 Phase다. 지금 구현된 것으로 화면에 넣지 않는다.

UI 디자인 파일만으로 Ticket 완료를 선언하지 않는다. 실제 업무 흐름·권한·경합·stale 검증 후 Head가 인수한다.

## 디자인 감사 후 검수 항목

- 상세: 매핑 후보 선택과 후속 검토 표시, 기록된/빈 결정 이력, 감사 변경 상세, 오래된 검토 대상·자기 승인·운영자 읽기 전용 상태.
- 목록: 제출자·제출일 필터와 페이지 이동. 공급사·상태 필터와 검색 유지.
- 목록 개선: 회사명 앞 두 글자(로고 없을 때)와 공급사별 동일 색, 상태 의미별 색상, 기본 20건 및 20/50/100 선택, 번호형 페이지 이동. 회사명은 가상 데이터이며 현재 목록 DTO에는 없으므로 연결 시 실제 공급사명 제공 경로를 확인하고 없으면 ID/기본 아이콘으로 표시한다.
- 검색은 청구번호/발주번호 선택 후 Enter 또는 버튼으로 적용하며 필터 변경·검색·표시수 변경 시 1페이지로 이동한다. 부분 검색은 사용자 승인된 변경이고 별도 backend Worker가 구현 중이다. invoiceNumber 정규화 후 포함, PO 대소문자 무시 포함, 공급사/제출자 정확 조건 유지. 시안의 로컬 필터를 실제 페이지 일부만 필터링하는 방식으로 연결하지 않는다.
- 공통: 로딩·데이터 없음·조회 실패·401·403 배치. 상태 선택기는 디자인 검수용이며 최종 서비스 UI에서 제거한다.
- 목록의 처리기한·예외 유형 요약은 현재 조회 계약에 없으므로 미표시. 요구사항/API 차이는 연결 단계의 확인 사항이며 임의 계산·새 백엔드 구현을 하지 않는다.
- 이 감사는 디자인 범위다. 실제 인증, cursor 조회, idempotency, 최신성 재조회 및 업무 상태 전이는 API 연결 후 검증한다.

## 후순위 디자인 작업

- 사용자 요청: 현재 연두색 주요 버튼이 다소 튀므로, 감사 완료 뒤 채도를 낮춘 세이지·올리브 계열 후보를 동일 화면에서 비교한다.
- 기존 테마는 후보 확인 전 변경하지 않는다. 일반/hover/disabled/focus 상태와 글자 대비, 다른 버튼과의 식별성을 함께 검수한다.
