# UI 표현과 디자인 기준

UI를 추가하거나 시각 표현을 변경할 때만 읽는다. 업무 흐름·역할·상태·화면 범위는 `Spec.md` 19절, 현재 구현은 `web/`가 기준이다. 화면/API 목록·연결 경과·검증 보고는 이 문서에 복제하지 않는다.

## 사용자 검수에서 정한 표현

- 안내 문구는 서버·DB 구현보다 사용자가 할 일과 조회 범위를 설명한다. 같은 안내를 여러 위치에 반복하지 않고 기술적인 경계값 설명은 오류가 있을 때 보여준다.
- 공급사 코드, 우리 회사 발주번호, 공급사 청구번호를 구분해 안내한다. 수동 입력은 실제 구매 자료·공급사 문서를 확인하는 흐름으로 설명한다.
- 품목 추가만 눌러 생긴 미사용 행은 저장·제출을 막지 않는다. 일부 입력한 행이나 기존 저장 행을 조용히 버리지 않으며 수정 또는 명시적 삭제를 안내한다.

## 시각 기준

- 따뜻한 회색 사이드바, 흰 본문, 얇은 경계, 올리브 텍스트와 라임 포인트의 차분한 업무 도구 분위기를 유지한다.
- 로고·색상 토큰·탭·표·버튼·패널은 기존 공통 요소를 사용한다. 새 테마·장식적 카드 대시보드·업무 판단에 도움이 없는 그래프·AI 채팅으로 임의 변경하지 않는다.
- 실제 데이터의 넘침·줄바꿈, 로딩·빈 화면·오류·권한 안내, 일반/hover/disabled/focus 상태와 글자 대비를 시각 검수한다.
- 미완성 기능이나 서버에 없는 업무 정보를 가상 데이터로 채우지 않는다. 기술적인 version/hash는 기본 업무 문구 대신 접힌 기술 정보에서 제공한다.

## 보류한 사용자 선호

- 주요 연두색 버튼의 채도를 낮춘 세이지·올리브 후보를 같은 화면에서 비교한다. 후보 확인 전 현재 테마를 바꾸지 않는다. 대비와 다른 버튼과의 식별성을 함께 확인한다.
